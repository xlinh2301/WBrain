# v0.1.0

Status: First development release.

## Changes

- Initial CPU OCR API with image upload and structured detection/recognition results.
- YOLO11m ONNX text detector with CPU post-processing and bounding-box output.
- EditCTC `s1024` CTC-only ONNX recognizer.
- Standardized model modules under `monolith/textdetection/` and
  `monolith/textrecognition/`.
- Docker Compose on-prem deployment with persistent database and logs.
- Vercel demo endpoint at `/api/v1/recognize`.
- Separate PC web UI and native-like mobile web UI with full-screen rear camera.
- Mobile image compression to reduce request-size failures such as HTTP 413.
- Mobile and PC result visualization with OCR bounding boxes and labels.
- Paddle/ONNX parity validation script; current test set produced identical
  text predictions for 500/500 images.

## Runtime artifacts

- Source tag: `v0.1.0`
- Detector: YOLO11m OBB exported ONNX
- Recognizer: EditCTC `s1024` exported ONNX, CTC branch only
- Runtime: CPU / ONNX Runtime
- Model binaries are release artifacts and are intentionally ignored by Git.

## Security and licensing

- Set `API_KEY` for protected deployments; never commit secrets.
- The Vercel demo has no persistence and should not be treated as the
  production data plane.
- Customer license, encrypted artifact packaging, image digests, SBOM and
  checksums remain release-engineering follow-up work.

## Known limitations

- The custom EditRefine branch is not included in the ONNX export; decoding uses
  the CTC branch.
- Recognition parity is verified, but ground-truth accuracy for the currently
  supplied `s1024` checkpoint has not been accepted as a production benchmark.
- Model files must be supplied separately when reproducing a deployment because
  `.onnx` artifacts are not tracked in Git.
- Privileged host administrators can inspect runtime memory and loaded libraries.
- TensorRT is not included in the CPU profile.
